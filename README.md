# Museum AI

Бэкенд и мобильное приложение для музейного гида. Пользователь фотографирует картину — приложение распознаёт её, дает возможность выделить границы на экране и возвращает историю от лица художника, аудиорассказ и фото художника.

## Как это работает

1. Пользователь делает снимок картины в мобильном приложении.
2. Пользователь настраивает рамку выделения пальцем, обрезая лишний фон.
3. Мобильное приложение отправляет обрезанное фото на `POST /experience`.
4. Сервер отправляет фото в Gemini (vision) — модель определяет название и автора картины.
5. Если картина есть в кураторской базе — берётся проверенная история; если Gemini узнала картину, но её ещё нет в базе — история генерируется на лету через LLM и кешируется на будущее.
6. В ответ приходят: данные о картине, рассказ от лица художника, ссылки на аудио и фото художника.

## Поддерживаемые картины

Распознаётся **любая всемирно известная картина**, которую способна узнать Gemini — список не ограничен. Отдельно выделены 15 картин с вручную написанными и проверенными историями (см. `backend/database/paintings.json`): Mona Lisa, The Starry Night, Girl with a Pearl Earring, The Scream, Guernica, The Persistence of Memory, American Gothic, The Birth of Venus, The Kiss, Las Meninas, The Night Watch, The Great Wave off Kanagawa, Liberty Leading the People, Impression Sunrise, Whistler's Mother. Для всех остальных известных картин история генерируется автоматически при первом сканировании.

## Технологии

### Бэкенд
- **Python 3.12**
- **FastAPI** — веб-фреймворк
- **uvicorn** — сервер
- **Google Gemini (vision)** — распознавание картины по фото и генерация истории
- **Pillow** — обработка изображений перед отправкой в Gemini
- **gTTS** — генерация аудио (Google Text-to-Speech)

### Фронтенд
- **React Native (Expo SDK 54)** — мобильное приложение
- **TypeScript** — язык разработки
- **React Navigation v7** — навигация
- **expo-camera** — работа с камерой
- **expo-image-manipulator** — обрезка изображений на клиенте
- **expo-av** — воспроизведение аудио

## Запуск

### Запуск бэкенда
Все команды — из **корня проекта** (`museum_ai/`), не из `backend/`: `main.py`
использует абсолютные импорты вида `from backend.routes import ...`, поэтому
запуск из `backend/` сломается с `ModuleNotFoundError`.

```bash
# Активировать виртуальное окружение (из корня проекта)
source venv/bin/activate

# Установить зависимости
pip install -r backend/requirements.txt

# Создать .env с ключом Gemini API (один раз)
cp backend/.env.example backend/.env
# и вписать в него: GEMINI_API_KEY=ваш_ключ

# Запустить сервер (обязательно так, с указанием backend.main)
# --host 0.0.0.0 нужен, чтобы сервер был виден с телефона в той же Wi-Fi сети
# (без него uvicorn слушает только 127.0.0.1, и телефон не сможет подключиться)
uvicorn backend.main:app --reload --host 0.0.0.0
```
Сервер запустится на `http://127.0.0.1:8000`
Документация API доступна на `http://127.0.0.1:8000/docs`

**Важно:** доступ к Gemini API из России сейчас требует VPN/прокси на машине,
где запущен бэкенд (это касается сервера, а не телефона пользователя музея —
телефон никогда не обращается к Gemini напрямую). Для реальной эксплуатации
имеет смысл разместить бэкенд на сервере вне России — тогда VPN не понадобится
уже никому.

### Запуск фронтенда
Перед запуском пропишите IP-адрес вашего компьютера (из сети Wi-Fi) в переменной `BASE_URL` в файле `frontend/services/api.ts`, чтобы телефон мог подключиться к локальному серверу.

```bash
# Перейти в папку фронтенда
cd frontend

# Установить npm-пакеты
npm install --legacy-peer-deps

# Запустить сборщик
npm start
```
Отсканируйте появившийся QR-код через приложение **Expo Go** на телефоне (версия 54.0.8). 

Если вы тестируете удаленно (компьютер и телефон в разных сетях), запускайте сборщик через тоннель:
```bash
npx expo start --tunnel
```

*Примечание: Чтобы тестировать интерфейс без запущенного бэкенда, просто нажмите на карточки картин внизу главного экрана приложения. Они откроются с использованием локальных оффлайн-файлов из папки `frontend/assets`.*

## API

| Метод | Endpoint | Описание |
|-------|----------|----------|
| GET | `/` | Проверка что сервер работает |
| POST | `/recognize` | Распознать картину по фото |
| GET | `/painting/{id}` | Данные о картине |
| GET | `/story/{id}` | Рассказ художника |
| POST | `/speech/{id}` | Сгенерировать аудио |
| GET | `/audio/{id}` | Получить аудиофайл |
| GET | `/artist/{id}` | Фото художника |
| POST | `/experience` | Всё сразу: распознавание + история + аудио |

## Добавление картины в кураторскую базу

Само распознавание работает без этого — Claude узнаёт любую известную картину
сама, а если её нет в базе, история сгенерируется автоматически. Ручное
добавление нужно только для того, чтобы гарантировать качество истории и
(опционально) настоящее фото художника вместо заглушки:

1. Добавить запись в `backend/database/paintings.json` (`id`, `title`, `artist`, `artist_id`, `year`, `story`) — `title`/`artist` лучше писать так, как их называет англоязычная Википедия, без диакритики, чтобы совпадать с ответом Claude.
2. *(Опционально)* Добавить фото художника в `backend/assets/artists/{artist_id}.jpg` — если фото нет, подставляется `placeholder.jpg`.
3. *(Опционально)* Для локальных тестов на фронтенде скопировать файлы художника `.jpg` и озвучки `.mp3` в `frontend/assets/` и прописать их в `MOCK_RESULTS` в `frontend/screens/HomeScreen.tsx`.
