# museum-ai

## О проекте
Приложение для музеев на FastAPI. Пользователь фотографирует картину,
приложение распознаёт её через Gemini (vision) и рассказывает историю от
лица художника — голосом (аудио) и текстом.

Распознавание работает для любой всемирно известной картины, которую
способна узнать LLM, — не ограничено конкретным списком. Два уровня базы:
- 15 кураторских картин в `paintings.json` — тексты историй написаны и
  проверены руками, качество гарантировано.
- Всё остальное, что узнаёт Gemini, — история генерируется автоматически при
  первом сканировании и кешируется в `generated_paintings.json`, чтобы не
  генерировать её заново при повторных сканах.

Разработчик — начинающий. Важно: объяснять происходящее, не перепрыгивать
через этапы, не предлагать сложную архитектуру раньше времени. Весь исходный
код в проекте пишет разработчик руками — Claude объясняет, проверяет и
указывает на ошибки, но не пишет исходный код за него (документацию вроде
этого файла — обновляет сам).

## Структура проекта
museum-ai/

backend/

├── main.py              — точка входа, запуск FastAPI-сервера

├── config.py            — загрузка GEMINI_API_KEY из .env

├── requirements.txt     — список библиотек проекта

├── .env / .env.example  — секреты (сам .env не в git)

├── routes/

│   ├── recognize.py     — POST /recognize, только id картины

│   ├── experience.py    — POST /experience, всё сразу (история+аудио+фото)

│   ├── paintings.py     — GET /painting/{id}

│   ├── stories.py       — GET /story/{id}

│   ├── speech.py        — POST /speech/{id}, GET /audio/{id}

│   └── avatars.py       — GET /artist/{id} (с заглушкой, если фото нет)

├── services/

│   ├── vision_recognizer.py — распознаёт картину на фото через Gemini (vision)

│   ├── image_matcher.py     — сопоставляет ответ Gemini с базой картин

│   ├── painting_db.py       — единая точка доступа к paintings.json + generated_paintings.json

│   ├── story_generator.py   — генерирует историю для картин не из кураторской базы

│   └── speech_generator.py  — текст в аудио (gTTS)

├── database/

│   ├── paintings.json            — кураторская база (в git)

│   └── generated_paintings.json  — автосгенерированный кеш (не в git)

└── assets/

├── artists/          — фото художников (.jpg) + placeholder.jpg

└── audio/            — сгенерированные mp3

## Принцип разделения
- **routes** — "дверь": принимает запрос, сам не думает
- **services** — "комната внутри": реальная логика

## План этапов
1. FastAPI запущен, GET / → {"status": "working"}  ✅ готово
2. POST /recognize — принимает изображение  ✅ готово
3. paintings.json с данными о картинах  ✅ готово
4. Распознавание двух картин (сравнение с эталонами, phash)  ✅ готово (заменено на этапе 10)
5. GET /painting/{id}  ✅ готово
6. GET /story/{id} — текст из JSON, без LLM  ✅ готово
7. POST /speech/{id} — генерация речи  ✅ готово
8. GET /artist/{id}  ✅ готово
9. POST /experience — всё сразу  ✅ готово
10. Распознавание через Gemini (vision) вместо phash + автогенерация историй
    для любых известных картин, не только из кураторского списка  ✅ готово
    и проверено живым запуском

## Статус
Этап 10 полностью реализован и проверен вживую в ветке
`feature/llm-painting-recognition`: сервер запускается (`uvicorn
backend.main:app --reload` из корня проекта), `/experience` с реальными фото
Mona Lisa и The Starry Night отдаёт корректный ответ (история, аудио, фото
художника), генерация истории для картин не из кураторской базы тоже
проверена. По пути поправили модель Gemini (`gemini-2.5-flash` оказалась
отключена — заменили на алиас `gemini-flash-latest`) и нестыковку в
запуске сервера (`main.py` использует абсолютные импорты, поэтому нужен
`uvicorn backend.main:app`, а не запуск из `backend/`). Ветка готова к мержу
в `main`.
